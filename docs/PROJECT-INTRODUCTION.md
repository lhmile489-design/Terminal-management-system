# Mile Terminal 项目介绍与使用指南

Mile Terminal 是面向 Windows 本地开发环境的终端与项目管理工作台。它把常用前端服务、一次性构建任务、本机监听端口和会话输出放在同一个桌面应用中，适合需要频繁启动、停止和排查多个本地项目的开发者。

它不是远程运维平台，也不会替你修改项目启动命令。应用只执行项目 `package.json` 中已经声明的脚本，并将项目检测、端口状态和运行会话集中展示。

## 安装与启动

Windows 发布包位于 `release/Mile Terminal Setup <version>.exe`。运行安装器后按向导选择安装目录，再从开始菜单启动 Mile Terminal。

从源码运行需要 Windows 与 Node.js：

```bash
npm install
npm run dev
```

首次启动后，先打开 **启动台**，将最常用的项目登记进来。

## 快速开始：添加并启动一个本地服务

1. 在 **启动台** 点击“添加服务”，或按 `Ctrl+K` 后选择“添加服务”。
2. 选择项目目录。应用会只读识别 `package.json`、锁文件和项目标记，显示框架、包管理器与可用脚本；这一过程不会执行项目代码。
3. 填写名称，选择一个已声明的启动脚本，例如 `dev`，然后添加到启动台。
4. 在服务卡片上点击“启动”。应用会先进行目录、脚本、运行时、依赖和预期端口等预检。
5. 启动成功后，卡片会显示状态、运行时间和实际捕获到的端口。点击端口号可在浏览器打开 `http://localhost:<port>`；点击“日志”进入该会话的终端。

没有可用脚本的项目可以“仅登记”：它仍会出现在工作台供观察，但不能从应用内启动。

## 服务与任务

| 类型 | 适合什么 | 主要操作 |
| --- | --- | --- |
| 服务 | 长时间运行的开发服务器、API、预览服务 | 启动、停止、重启、打开浏览器、查看端口 |
| 任务 | `build`、代码生成、一次性脚本 | 运行、中止、查看结果与产物目录 |

服务可设置“预期端口”，用于预检和冲突提示；实际端口始终由项目自身决定。任务不设置端口，结束时会按退出码显示成功、失败或取消，并可在设置中开启系统通知。

服务卡片支持置顶、鼠标拖拽排序和键盘 `Ctrl+方向键` 排序。编辑服务时可选择自动框架字标或预设图标；图标只是显示设置，服务运行中也能修改，不会重启进程。运行中的服务只允许修改名称、置顶与图标，目录、脚本、端口和环境变量需要先停止服务。

## 六个视图

### 工作台

工作台持续显示当前用户的监听端口、进程 CPU/内存、运行时长和系统概览。监听项分为“我的服务”和默认折叠的“应用后台”；可将某个进程调整到适合自己的分组。新出现且未纳管的本地监听服务可直接加入启动台。

### 启动台

这是日常操作中心。每张卡片提供启动或运行、停止或中止、重启、日志、诊断、编辑、打开项目目录和移除等操作。任务成功后可打开产物目录。卡片出现“端口重合”时，表示多个已运行条目使用了同一个端口，浏览器只能访问其中一个，应修改其中一项的配置。

### 终端

终端按会话保存原始输出和交互输入。启动条目后，可从卡片的“日志”按钮跳到对应会话；也可以新建一个 PowerShell 会话。终端字号和回滚行数可在设置中调整。

### 日志

日志中心把多个会话的输出汇总为可检索的行，可按会话、级别（信息、警告、错误）和关键字筛选。日志只保存在内存，最多保留最近 5000 行；需要查看完整交互输出时请使用终端视图。

### 诊断

为指定条目重新收集并展示：预检结果、预期端口的占用者、最近一次退出码和运行时长、首个错误行、Node 与包管理器信息，以及注入环境变量的键名。环境变量值不会显示在界面或诊断日志中。诊断结果会提供安全的修复入口，例如重新选择目录、选择脚本或处理端口冲突。

### 设置

可调整采集周期（1、2、5 或 10 秒）、浅色/深色/跟随系统主题、外部终端、终端字号与回滚行数，还可控制：

- 退出应用时是否停止本应用启动的受控进程
- 关闭窗口时是否收起到托盘
- 任务自然结束时是否发送 Windows 系统通知

设置会立即保存，无需单独点击保存按钮。

## 端口冲突如何处理

预检或诊断发现预期端口被占用时，先确认占用者：

- 若占用者由 Mile Terminal 启动，界面会提供精确的“停止它”入口。
- 对已识别的 Next.js 服务，可选择新的端口；应用会在下次启动时注入 `PORT`，并同步更新预期端口。
- 对其他框架，应用只提供项目配置或环境变量的操作指引，不会猜测变量名，也不会在命令后追加 `--port`。

不要仅依据端口号终止进程。相同端口可能同时被 IPv4 与 IPv6 监听，或被多个不同来源的进程使用；Mile Terminal 只会停止经过运行令牌、进程组和当前用户校验的受控进程。

## 快捷操作

按 `Ctrl+K` 打开全局命令面板：

- 输入服务名或项目路径，快速启动或停止条目。
- 输入纯数字端口号，定位工作台中的对应监听项。
- 输入脚本名，运行已登记项目中的声明脚本。
- 以 `>` 开头搜索内置操作，例如添加服务、刷新采集、切换主题或跳转视图。
- 使用方向键选择、`Enter` 执行、`Esc` 关闭。

## 安全与数据边界

- 项目识别只读文件，不会自动安装依赖或执行检测到的代码。
- 缺少依赖时，预检会明确提示；只有你主动创建安装会话时才会运行安装命令。
- 运行命令必须来自目标项目已声明的脚本，应用不会拼接任意命令行参数。
- 外部进程可以被观察和诊断，但不会仅因占用相同端口而被终止。
- 配置保存在 `%APPDATA%\mile-terminal\config.json`，包含登记条目和偏好设置；会话日志不落盘。

## 常见问题

### 服务无法启动

打开服务卡片的“诊断”，先查看预检中失败的项目。常见原因是项目目录不存在、脚本已经变更、包管理器或 Node 不可用、依赖未安装，或预期端口被其他进程占用。按诊断提供的入口修复后再启动。

### 服务正在运行，但没有显示端口

应用会从启动输出中捕获常见的本地地址。若服务在 60 秒内仍存活但没有可识别的端口，会显示“端口未知”，而不是误判为失败。请查看终端输出，或在编辑中填写预期端口以获得冲突检测。

### 想修改运行服务的端口或环境变量

先停止服务，再在“编辑”中修改。运行中的进程仍使用启动时的目录、脚本、端口和环境变量；为了保证停止操作只作用于正确的进程，这些字段在运行期间会锁定。

### 为什么没有自动执行 `npm install`

依赖安装可能执行项目的 `postinstall` 脚本。为避免在未确认的项目目录中运行代码，Mile Terminal 只显示预检结果，并要求你主动创建安装会话。
