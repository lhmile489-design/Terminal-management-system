# Mile Terminal 项目介绍与使用指南

Mile Terminal 是面向 Windows 本地开发环境的终端与项目管理工作台。它把常用前端服务、后端服务、一次性构建任务、本机监听端口和会话输出放在同一个桌面应用中，适合需要频繁启动、停止和排查多个本地项目的开发者。

它不是远程运维平台，也不会替你修改项目启动命令。应用只执行项目 `package.json` 中已经声明的脚本（Spring Boot、Python、Go、Rust、C++ 等生态使用固定的启动方式），并将项目检测、端口状态和运行会话集中展示。

## 安装与启动

Windows 发布包位于 `release/Mile Terminal Setup <version>.exe`。运行安装器后按向导选择安装目录，再从开始菜单启动 Mile Terminal。再次双击快捷方式只会把已有窗口带回前台，不会起第二个实例。

从源码运行需要 Windows 与 Node.js：

```bash
npm install
npm run dev
```

首次启动后，先打开 **服务** 页，把最常用的项目登记进来。

## 五个页面

左侧导航轨 5 项，`Ctrl+1` 到 `Ctrl+5` 直接切换。

| 页面 | 做什么 |
| --- | --- |
| 总览 | 默认首页。统计磁贴、按打开次数列出最常用的 5 个服务可直接启停、顶部待办条、每 2 秒刷新的监听端口表 |
| 服务 | 按工作组分段管理前端、后端与批处理任务；点一行在右侧分栏打开详情 |
| 终端 | 自建 PowerShell 会话与服务会话；「全部输出」跨会话汇总日志 |
| 设置 | 采集周期、主题、终端、退出行为、通知、全局快捷键、配置导入导出 |
| 关于 | 版本、教程、快捷键一览、项目仓库与 Issue 入口 |

实时动态（启停、预检、告警）收在标题栏按钮打开的抽屉里。

## 快速开始：添加并启动一个本地服务

1. 在 **服务** 页点击「添加服务」，或按 `Ctrl+K` 后选择「添加服务」。
2. 选择项目目录。应用会只读识别 `package.json`、锁文件和项目标记，显示框架、包管理器与可用脚本；这一过程不会执行项目代码。选到已登记过的目录时会提示是哪个条目。
3. 填写名称，选择一个已声明的启动脚本，例如 `dev`，然后添加。
4. 在服务行上点击「启动」。应用会先做目录、脚本、运行时、依赖和预期端口等预检。
5. 启动成功后，行上会显示状态、运行时间和实际捕获到的端口。点击端口号可在浏览器打开 `http://localhost:<port>`；详情的「输出」标签是该会话的终端。

没有可用脚本的项目可以「仅登记」：它仍会出现在列表里供观察，但不能从应用内启动。

### 一次添加很多个项目

在服务页点「导入文件夹」，选一个父目录。应用只读扫描它下面一层子目录（最多 60 个），列出识别出的项目让你勾选后批量添加。已登记过的目录会置灰并标出是哪个条目；识别和校验与单个添加完全相同，不会安装依赖或执行任何代码。

## 服务与任务

| 类型 | 适合什么 | 主要操作 |
| --- | --- | --- |
| 服务 | 长时间运行的开发服务器、API、预览服务 | 启动、停止、重启、打开浏览器、查看端口 |
| 任务 | `build`、代码生成、一次性脚本 | 运行、中止、查看结果与产物目录 |

服务可设置「预期端口」，用于预检和冲突提示；实际端口始终由项目自身决定。任务不设置端口，结束时按退出码显示成功、失败或取消，并可在设置中开启系统通知。

运行中的服务只允许修改名称、分类、工作组与图标，目录、脚本、端口和环境变量需要先停止服务。图标只是显示设置，修改不会重启进程。

## 服务页

- 列表按工作组分段，未分组排最后。类型筛选、运行状态筛选和搜索（名称、端口、路径、分类）可以同时用。
- 点一行在右侧打开详情，五个标签：概览、输出、诊断、构建（仅 Spring Boot）、配置。配置标签里直接编辑，分「常用 / 高级」，有未保存改动时切换会提醒。
- 拖动成员行可以换工作组、组内排序；键盘用 `Ctrl+↑` / `Ctrl+↓`。
- 整组「启动全部 / 停止全部」。生产环境的任何启动、沙箱环境的 Spring Boot 启动，都会先弹确认。
- 行上的「⋯」菜单有「在此目录开终端」（应用内新开一个 PowerShell 会话）和「在外部终端打开」（用设置里选的 Windows Terminal / PowerShell / CMD / Git Bash）。目录都由主进程按登记信息解析，不会开到登记范围以外。

键盘操作：`↑` / `↓` 移动选中行，`Enter` 打开详情，`Space` 启停（组头上是整组），`Ctrl+Tab` / `Ctrl+Shift+Tab` 切详情标签，`Esc` 关闭详情。焦点在输入框或终端里时这些快捷键让给输入。

### 按依赖顺序启动

在条目配置里可以设「先等待」哪些同组条目。整组启动时按依赖分层：同一层并发启动，下一层等上一层都进入运行中。某个前置服务一直不报端口时，等 60 秒按「端口未知」继续。前置没起来的（被预检拦下、崩溃、出错），依赖它的条目会跳过，并写明原因。

「先等待」不能指向自己、不能指向不存在的条目、不能成环。托盘的「启动全部」同样按这个顺序。

## 总览页

- 顶部待办条：预期端口被别的进程占用（写明进程名和 PID）、服务预检未通过或异常退出、端口采集失败，各成一行，点「查看诊断」直达该服务；没有待办时显示「一切正常」。
- 监听端口表分「我的服务」和默认折叠的「应用后台」。每行的「⋯」菜单可以跳到对应服务、复制端口 / PID / 目录、打开目录，菜单里没有终止进程的入口。

## 终端页

终端按会话保存原始输出和交互输入。服务页详情的「输出」标签、「在此目录开终端」都会落到这里的会话。终端里按 `Ctrl+F` 搜索输出，显示「第 n / 共 m 条」，`Enter` 下一条，`Shift+Enter` 上一条，`Esc` 关闭。

「全部输出」把多个会话的输出汇总为可检索的行，可按会话、级别（信息、警告、错误）和关键字筛选，点日志行可跳回所在会话。日志只保存在内存，最多保留最近 5000 行。

## 诊断与崩溃现场

详情的「诊断」标签会重新收集：预检结果、预期端口的占用者、最近一次退出码和运行时长、首个错误行、Node 与包管理器信息，以及注入环境变量的键名。环境变量的值不会显示在界面或诊断日志中。

服务退出后，诊断的「会话回顾」里还会有：

- 最后错误行：退出前输出里的最后一个错误行（npm 自己追加的收尾块之外优先）。
- 退出前输出：最后 30 行可见输出，已去掉颜色码，可以一键复制。

这些只保存在内存里，不写磁盘。

## 设置

设置页分 6 节，每项改动立即保存：

1. 采集：周期 1、2、5 或 10 秒。
2. 外观：浅色 / 深色 / 跟随系统。
3. 终端：外部终端选择、字号、回滚行数。
4. 退出行为：关闭到托盘、退出时是否结束本应用启动的进程、隐藏任务栏图标、全局快捷键。
5. 通知：任务完成、服务崩溃或被拦、只在窗口收起或失焦时弹。
6. 配置：导出与导入，见下。

### 配置导出与导入

换机器或重装系统时用。

- 导出：把条目、工作组、忽略规则、手动分组和关注关键字写进一个 JSON 文件。环境变量只带变量名、不带值，自定义图片不导出。
- 导入：先把当前配置整份备份成 `config.before-import-<时间>.json`（放在配置目录里，导入结果不满意时可以手动换回），再合并。同目录同脚本已登记的条目跳过；目录在这台机器上不存在的跳过并写明原因；同名工作组复用；「先等待」换成新条目的 id；忽略规则和关注关键字取并集；设置不覆盖。
- 导入的条目没有环境变量值，结果里会列出哪些条目需要你重填。
- 格式不对的文件会被直接拒绝，配置保持不变。

## 窗口收起后

窗口收起到托盘后仍能操作：托盘菜单显示运行数，可以按工作组「启动全部 / 停止全部」、点最近使用的服务启停、一键全部停止，生产环境照样先确认。

- 服务崩溃、启动被预检拦下、重启后端口迟迟不释放时弹系统通知，崩溃通知正文带最后错误行，点通知直达该服务的输出或诊断。默认只在窗口收起或失焦时弹。
- `Ctrl+Alt+M` 在任何程序里唤回窗口并打开命令面板（设置里可关；被别的程序占用时只在实时动态里提示）。
- 窗口位置、大小、上次停留的页面和选中的服务，重启后恢复。

## 端口冲突如何处理

预检或诊断发现预期端口被占用时，先确认占用者：

- 若占用者由 Mile Terminal 启动，界面会提供精确的「停止它」入口。
- 对已识别的 Next.js 服务，可选择新的端口；应用会在下次启动时注入 `PORT`，并同步更新预期端口。
- 对其他框架，应用只提供项目配置或环境变量的操作指引，不会猜测变量名，也不会在命令后追加 `--port`。

不要仅依据端口号终止进程。相同端口可能同时被 IPv4 与 IPv6 监听，或被多个不同来源的进程使用；Mile Terminal 只会停止经过运行令牌、进程组和当前用户校验的受控进程。

## 命令面板

按 `Ctrl+K` 打开：

- 输入服务名或项目路径，快速启动、停止、重启、查看详情、打开目录、开终端。
- 输入工作组名，启动全部 / 停止全部。
- 输入纯数字端口号，定位总览中的对应监听项。
- 输入脚本名，运行已登记项目中的声明脚本。
- 添加条目、切换主题、跳转页面。
- 方向键选择，`Enter` 执行，`Esc` 关闭。`?` 打开快捷键一览。

## 安全与数据边界

- 项目识别只读文件，不会自动安装依赖或执行检测到的代码。
- 缺少依赖时，预检会明确提示；只有你主动创建安装会话时才会运行安装命令。
- 运行命令必须来自目标项目已声明的脚本，应用不会拼接任意命令行参数。
- 外部进程可以被观察和诊断，但不会仅因占用相同端口而被终止。
- 环境变量的值只留在主进程，界面和导出文件里都只有变量名。
- 配置保存在 `%APPDATA%\mile-terminal\config.json`，包含登记条目和偏好设置；会话日志和崩溃现场不落盘。

## 常见问题

### 服务无法启动

打开详情的「诊断」，先查看预检中失败的项目。常见原因是项目目录不存在、脚本已经变更、包管理器或 Node 不可用、依赖未安装，或预期端口被其他进程占用。按诊断提供的入口修复后再启动。

### 整组启动时有的服务没起来

看实时动态里的汇总：写明「前置服务没起来：<名称>」的，是它等的那个服务被预检拦下、崩溃或启动出错，先处理前置服务，再重新启动。

### 服务正在运行，但没有显示端口

应用会从启动输出中捕获常见的本地地址。若服务在 60 秒内仍存活但没有可识别的端口，会显示「端口未知」，而不是误判为失败。请查看输出，或在配置里填写预期端口以获得冲突检测。

### 想修改运行服务的端口或环境变量

先停止服务，再到详情的「配置」标签修改。运行中的进程仍使用启动时的目录、脚本、端口和环境变量；为了保证停止操作只作用于正确的进程，这些字段在运行期间会锁定。

### 导入配置后某个服务启动报缺环境变量

导出文件不带环境变量的值。导入结果里会列出每个条目需要重填的变量名，到详情的「配置」标签里补上。

### 为什么没有自动执行 `npm install`

依赖安装可能执行项目的 `postinstall` 脚本。为避免在未确认的项目目录中运行代码，Mile Terminal 只显示预检结果，并要求你主动创建安装会话。
