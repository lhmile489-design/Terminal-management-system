# Mile Terminal

Windows 本地终端与前端项目管理工作台。个人自用工具，把「本机现在跑着什么」和「我常跑的那几个项目」放在同一个界面里。

不是终端模拟器的替代品，也不是运维平台。它解决的是一类具体的日常摩擦：想知道 5173 端口是谁占的、想一键起停几个常用服务、想在跑完 build 之后收到一声提醒、想在一个地方回看刚才几个会话的输出。

技术栈 Electron 43 + React 19 + TypeScript + Vite + Tailwind 4，原生终端用 node-pty。目标平台 Windows 11。

## 五个页面

左侧导航轨 5 项，`Ctrl+1`–`Ctrl+5` 直接切换。

| 页面 | 做什么 |
| --- | --- |
| **总览** | 打开应用的默认页。统计磁贴（运行中服务、监听端口、端口冲突、系统负载），「服务操作台」按打开次数列出最常用的 5 个服务可直接启停，下方是每 2 秒刷新的监听端口表，分「我的服务」与「应用后台」两组。 |
| **服务** | 按工作组分段管理前端、后端与批处理任务。点一行在右侧分栏打开详情，五个标签：概览 / 输出 / 诊断 / 构建 / 配置。支持搜索（含分类）、运行状态筛选、组内与跨组拖动排序、整组启停。 |
| **终端** | 自建 PowerShell 会话与服务会话分段列出，xterm + WebGL；「全部输出」跨会话汇总，按级别与关键字检索，日志行可跳回所在会话。 |
| **设置** | 采集周期、主题、终端字号与回滚行数、关闭到托盘、退出时结束本应用启动的进程、任务完成与服务崩溃通知、全局快捷键开关。 |
| **关于** | 版本、使用教程、快捷键一览、项目仓库与 Issue 入口。 |

实时动态（启停、预检、告警）收在标题栏按钮打开的抽屉里。全局命令面板（`Ctrl+K`）可以搜服务、搜端口、跑脚本、添加条目、切主题、跳页面；`?` 打开快捷键一览。窗口收起或在别的程序里时，按 `Ctrl+Alt+M` 唤回窗口并直接打开命令面板（设置里可关）。

窗口收起到托盘后仍能操作：托盘菜单显示运行数，可以按工作组「启动全部 / 停止全部」、点最近使用的服务启停、一键全部停止，生产环境照样先确认。服务崩溃、启动被预检拦下、重启后端口迟迟不释放时弹系统通知，点通知直达该服务的输出或诊断；默认只在窗口收起或失焦时弹。窗口位置、大小、上次停留的页面和选中的服务在重启后恢复；再次双击快捷方式只会把已有窗口带回前台，不会起第二个实例。

服务页键盘操作：`↑` / `↓` 移动选中行，`Enter` 打开详情，`Space` 启停（组头上是整组），`Ctrl+↑` / `Ctrl+↓` 组内调整顺序，`Ctrl+Tab` 切详情标签，`Esc` 关闭详情。焦点在输入框或终端里时这些快捷键让给输入。

除 npm 生态外，Spring Boot（Maven / Gradle wrapper、jar）、Python（入口文件、模块、uvicorn、Flask、Django）、Go、Rust、C++ 可执行文件可以选择固定的启动方式；命令形状由主进程按枚举构造，用户只能填相对项目根的路径或模块名。

服务可选自动框架字标、预设图标或上传自定义图片。图标只改变展示，运行中也能切换，不会重启进程、更改命令、端口或环境变量。

## 四个设计立场

这个工具的大部分设计取舍来自四条自我约束。它们不是实现细节，会直接影响你能期待它做什么、不做什么。

### 1. 不安装依赖，不执行项目代码

识别项目类型只读 `package.json`、锁文件和标记文件（`go.mod`、`manage.py`、`Cargo.toml` 等），连 `hugo version`、`pip show`、`go list` 这类看起来无害的版本查询都不跑。

代价是明确的：**缺 `node_modules` 时不会自动装。** 预检会把它报成 `fail` 并给出一个「创建安装会话」的按钮，由你自己点。因为 `npm install` 会执行 postinstall 脚本，那就等于替你运行任意代码。

同理，识别出 Go / Rust / Hugo / Django 这类生态时只给它一个准确的名字并标为「仅登记」—— 启动路径写死为 `<包管理器> run <脚本>`，这些生态推不出那个命令形状，硬猜等于替你构造命令。

### 2. 不会因为端口相同就杀死外部进程

能不能终止一个进程，只由三重凭据决定：启动时下发的运行 token、进程组、当前用户 UID。

界面上的「启动来源」徽标（VS Code / Windows Terminal / 本应用…）是沿父链按进程名推断的，而进程名是进程自己可以随便写的 —— 所以它**只用于显示，绝不参与终止授权**。一个把自己改名叫 `code.exe` 的进程不会因此变得可杀。手动分组同理，只影响它显示在哪一组。

kill 之前还会重新验证一次归属，因为 PID 会被复用。判定用的是操作系统记录的进程创建时间：根进程第一次出现在进程表里时钉住它的创建时间，之后同一个 PID 的创建时间变了，就说明原进程已退出、PID 被分给了别人；「子进程」创建得比根进程还早，也不算它的后代。终止时还要求命中的会话就是要停的那个会话。

### 3. 明确失效的东西，不让你先失败一次

启动前静态检查工作目录、脚本声明、运行时可用性、端口冲突。查出问题直接给修复入口，而不是让你点了启动、等它跑挂、再去读报错。预检本身只读文件系统，不写、不装、不执行。

### 4. 日志只留在内存

跨会话日志是环形缓冲 5000 行，不落盘。落盘就要连带处理保留期、体积上限，以及「输出里可能有密钥」这些问题 —— 而这个工具的用途是看当下这轮跑得怎么样，不是审计。

## 界面风格

「便当网格 + 微交互」：40px 标题栏、可折叠导航轨（184 / 56px）、磁贴式分区。浅色为主，深色与跟随系统可选。权威说明在 `docs/UI/UI-REFACTOR.md`。

- 圆角三档（卡片 16 / 控件 10 / 胶囊），阴影三档（静态 / 悬停 / 浮层）；深色只留浮层阴影，层次靠描边。
- 标题与数字用 Manrope，正文 Segoe UI + 雅黑，端口与路径用 Cascadia。图标统一 Phosphor，只有 16 / 20 两档。
- 状态色只染描边、图标块和胶囊，不染卡片底。全应用不用渐变底色，标题栏与关于页的品牌标识直接显示 logo。
- 按钮按下缩到 0.96，松开 spring 回弹；`prefers-reduced-motion` 下去掉位移和缩放。高斯模糊只用于命令面板、对话框这类固定浮层。
- 浮层统一走一个栈：`Esc` 只关最上层，焦点陷阱，关闭后焦点回到打开它的元素。危险操作用应用内确认框。

文字对比度全部 ≥ 4.5:1，深浅两套主题分别校验。禁用态不压整块透明度，改用弱化底色加可见边框，保证禁用的按钮文字也能读清。

## 开发

需要 Windows 和 Node 20+；发布构建推荐使用 Node 22 LTS。

```bash
npm install
npm run dev        # 开发模式
npm run typecheck  # node + web 两套 tsconfig
npm run build      # 构建到 out/
npm run build:win  # NSIS 安装包 → release/
```

## Windows 发布

生成 Windows x64 安装包：

```bash
npm run build:win
```

构建完成后，`release/` 中会生成 `Mile Terminal Setup <version>.exe` NSIS 安装器及其 `.blockmap` 文件；`release/win-unpacked/` 用于本机检查已打包的应用。项目随 `node-pty` 分发的 Windows x64 预编译模块打包，避免在发布阶段重复编译该原生依赖。

代码分布：

```
src/main/       主进程。所有特权操作、命令构造与参数校验都在这里
src/preload/    contextBridge 白名单，向渲染层暴露 window.mile.*
src/renderer/   React + zustand + Tailwind。只做展示与交互，没有任何特权
src/shared/     两侧共用的类型与 IPC 频道名
scripts/        验证脚本与夹具项目
```

渲染层拿不到运行 token、不能构造命令、不能指定要执行的可执行文件或工作目录。「新建终端」只能开主进程决定的固定 shell；所有 IPC 只接受主窗口主框架的请求；顶层页面不能被导航离开应用。外链只开两类地址：`localhost` 端口，以及写死在主进程里的项目仓库与 Issue 页。

## 验证方式

没有单元测试，用的是 41 个验证脚本：40 个启动真实主进程、加载真实构建产物、用 `executeJavaScript` 驱动真实渲染层，逐条断言并打印量到的数值；另 1 个（`verify-review-ownership.cjs`）用 esbuild 单独打包归属判定逻辑，喂合成进程表验证 PID 复用防护。每个脚本都在临时目录里放配置，不碰你真实的 `%APPDATA%`。

```bash
npm run build
npx electron scripts/verify-m10.cjs
npx electron scripts/verify-services.cjs
node scripts/verify-review-ownership.cjs
```

完整清单与跑法见 `CLAUDE.md`。安全与竞态类修复都做过反向对照：临时还原修复、确认恰好目标断言变红，再恢复并重新构建。

选择这种方式而不是单元测试，是因为这个项目里最容易出错的地方都在真实环境的接缝上：ConPTY 的输出形状、Windows 进程表、CSS 变量在两套主题下的实际计算值、IPC 的结构化克隆行为。这些用 mock 验证不了 —— 而一个基于错误 mock 的通过断言，比没有断言更危险。

界面断言读 `getComputedStyle` 与 `getBoundingClientRect`，不看截图：截图能证明「没崩」，证明不了圆角是 12px、对比度是 4.62:1。

`docs/PRD.md`（仓库父目录）逐个里程碑记录了实测结果，以及过程中被逮到的每一处真实缺陷与每一处「测试写错了、代码是对的」。

### 2.1.0（2026-10-28）

窗口收起后也能用：系统通知、托盘启停、全局快捷键，加上一轮复审修复。配置结构版本 9 → 11，启动时自动迁移，新加的开关默认都开，已有条目与工作组原样保留。

**新功能**

- 系统通知：服务崩溃、启动被预检拦下、重启后端口 5 秒未释放时弹通知，点击直达该服务的输出或诊断。默认只在窗口收起、最小化或失焦时弹；自己按停止不算崩溃；退出清理期间不弹。设置里有两个开关。
- 托盘菜单：顶部显示「N 个运行中」，tooltip 同步；按工作组启动全部 / 停止全部、最近使用的 5 个服务点一下启停、全部停止。生产环境任何启动、沙箱环境的 Spring Boot 启动都弹确认框，规则与界面里一致。

- 窗口位置、大小、最大化状态，以及上次停留的页面和选中的服务，重启后恢复。拔掉副屏后留在屏幕外的坐标会被丢弃；高缩放下窗口不会越开越大。
- 单实例：再次打开只把已有窗口带到前台，两个实例不再抢同一份配置。仅打包版生效。

**图标与界面**

- 窗口与托盘改用多尺寸 `.ico`（12 档，含 125%–175% 缩放会用到的尺寸），缩放算法换成面积平均并对小尺寸轻度锐化，任务栏、托盘、桌面图标不再发糊。
- 标题栏与关于页的品牌标识去掉渐变底，直接显示 logo；全应用不再用渐变底色。
- 服务页列表行加高、加间距，图标放进统一底块，标签与框架名同一行；详情打开后列表变窄时分类标签让位给名称。

**安全**

- 环境变量的值不再发到界面：条目列表、编辑回执、广播里只剩变量名。编辑改为合并补丁，留空表示保持原值，删除一行才会删掉该变量；面板打开期间别处新增的变量不会被误删。

**修复**

- 删除运行中的服务后，界面不再残留一条已不存在条目的运行态。
- 刚启动的服务点停止，偶尔被误判为「非本应用启动」而拒绝；归属重校验的缓存现在同时检查进程表和当前用户进程集。
- 添加对话框：连续换目录时旧的识别结果不再覆盖新的；连点「添加」只建一条。
- 拖动排序失败时回滚到原顺序。
- 上次选中的服务被删除后，清掉残留的记录。

**验证**

- 验证脚本 34 → 41 个，新增 `review-remove`、`review-env`、`review-notify`、`review-tray`、`review-window`、`review-single`、`review-hotkey`，每个都先在旧代码上跑出失败再修。发版前全套 41 个 0 失败，并做了一轮对改动的对抗审查。

界面整体重做，并修掉一轮项目级审查发现的安全与稳定性问题。配置结构版本仍是 9，从 1.7.0 升级不需要迁移，已有条目与工作组原样保留。

**界面重构（不兼容旧的页面结构）**

- 六个视图（工作台 / 启动台 / 终端 / 日志 / 诊断 / 设置）合并为五个页面（总览 / 服务 / 终端 / 设置 / 关于）。启动台与诊断并入服务页的详情分栏，日志并入终端页的「全部输出」。
- 新外框：40px 标题栏、可折叠导航轨、实时动态改为抽屉、`Ctrl+1–5` 切页、`?` 快捷键一览。
- 服务页：工作组分段磁贴、成员行、右侧详情五个标签（概览 / 输出 / 诊断 / 构建 / 配置）；配置标签直接编辑，分「常用 / 高级」，切走前提示未保存改动；运行状态筛选、按分类搜索；组内与跨组拖动排序（插入线），菜单与 `Ctrl+↑↓` 提供键盘替代并有读屏播报。
- 总览页：统计磁贴、按打开次数取前 5 的服务操作台、两列操作区。
- 设置页改 2 列分组磁贴，关于页改便当网格，教程按新结构重写。
- 设计令牌与组件层：三档圆角与阴影、Manrope 字体、统一的 Button / Tile / Segmented / Tabs / Menu / SplitPane / DialogShell / Drawer / 确认框 / Toast；对话框与命令面板接入统一浮层栈。
- 视觉门禁写进 `verify-ui.cjs`：文字色不加透明度、字号不低于 12px、不用任意值圆角、占位符不加透明度、禁用态不压整块透明度。

**安全**

- 「新建终端」IPC 不再接受渲染层传入的可执行文件、参数、工作目录和环境变量，只开主进程决定的固定 shell。
- 所有 IPC 只认主窗口主框架；顶层页面不能被导航离开应用。
- 新建条目与编辑走同一套逐字段校验：项目目录必须存在且为绝对路径，产物目录、jar / 入口路径必须相对项目根且不含 `..`，脚本必须在项目 `scripts` 里。打开路径的白名单在读取侧也不再信任旧配置里的绝对路径。
- 归属判定用操作系统记录的进程创建时间识别 PID 复用，终止前还核对会话一致。

**稳定性**

- 退出时开启「结束本应用启动的进程」后，会等进程树真正终止再退出（上限 6 秒），dev server 不再留在后台占端口。
- 主配置损坏、从 `.bak` 恢复时，坏文件另存为 `config.json.corrupt`，唯一的良好备份不再被覆盖。
- 端口采集失败时界面会显示失败状态，不再静默停在旧数据；窗口关闭后主进程不再往已销毁的窗口推送。
- 终端切换会话时，迟到的历史回放不再写进已销毁的终端。

**行为调整**

- 服务操作台的「停止」与「强制关闭」合并为一个按钮：两者原本调用完全相同，名称与行为对不上。停止仍是先发 Ctrl+C、3 秒后结束进程树。
- 关于页「GitHub 仓库」「提交 Issue」恢复可用（以前点了没有反应）。
- 焦点在输入框里时 `Ctrl+Tab` 不再切走详情标签。
- 端口真被另一进程占用时，预检优先给出「停止它」；一键改端口只对 Next 生效并同步 `PORT`。

**验证**

- 验证脚本 23 → 34 个，新增 8 个 `review-*` 覆盖上面的安全与稳定性修复。
- 修正若干假绿断言：对话框 `aria-modal` 检查以前从不打开对话框；停止检查以前把崩溃也算成功；Spring Boot 负向用例以前靠「运行中锁定」的报错通过。
- 停用三个没有配置沙箱、会读写真实配置的旧脚本。
